# HAKONIWA — はじまりの庭

AIが「神」として一日ひとつずつ世界を育てる、長期運営型の箱庭RPGのプレイアブルUIプロトタイプです。

## ローカル起動

```bash
npm install
npm run dev
```

## 体験できること

- Day 3時点の、一画面に収まる小さな長方形の村
- ピクセルレトロなトップビューで、キーボードやスマホ用方向ボタンを使う自由移動
- 木、池、家、井戸を調べ、世界の短い反応を読む探索
- 世界の変化を物語として残す「創世記」
- 他の観測者の匿名の願いと、自分の願いの投稿体験
- 上限を示さない図鑑と、神が創っていない花の発見
- まだ何もできない余白を残した個人の庭

投稿した願いは、このフロントエンドだけのプロトタイプではブラウザの `localStorage` に保存されます。

## 本番アーキテクチャ

静的フロントエンドは Cloudflare Pages、共有世界のAPIは Cloudflare Workers、データは D1 と R2 を想定します。毎日の創造だけは、さくらインターネットのVPS上の cron から実行します。

```text
観測者 ──> Cloudflare Pages ──> Workers API ──> D1 / R2
                                      ^
                                      │ 署名付き POST /admin/creation-cycle
                               さくらVPS cron
                                      │
                              AI生成 + 整合性検証
```

### 一日の創造サイクル

1. VPSのcronが世界スナップショット、直近の歴史、未解決の伏線、集約済みの行動・願いを取得する。
2. AIに「提案」をJSONで生成させる。AIへ直接DB更新権限は渡さない。
3. 決定論的な検証器が、既存法則との矛盾、規模、禁止事項、参照ID、ロールバック可能性を検査する。
4. ステージング世界で生態系シミュレーションを走らせ、破壊的な結果は保留する。
5. 承認済みイベントを一つのトランザクションで適用し、創世記と公開用の短い神託を保存する。
6. Workersがキャッシュを更新し、全観測者に同じ世界日を公開する。

### 最小データモデル

- `world_days`: 世界日、神託、公開時刻、生成モデル、検証結果
- `world_entities`: 生物・場所・概念・法則。誕生日と消滅日を持つ
- `relationships`: 捕食、成長、開花、発明など因果関係のグラフ
- `wishes`: 暗号化した作者ID、本文、状態（願い／届いた／叶った）
- `wish_links`: 願いと世界要素・創世記イベントの関係
- `observations`: 発見日、場所、第一発見者、最終確認日
- `player_gardens`: 観測者ごとの庭の状態
- `traces`: 焚き火跡や植樹など、期限付きの匿名の痕跡
- `mysteries`: 伏線、公開条件、AIだけが読む非公開メモ

願いはランキングに使わず、AIへ渡す際も人数ではなく意味的な多様性を残してサンプリングします。他人の行動ログは生データで渡さず、「池を観察した者が多かった」など個人を特定できない世界の記憶へ集約します。

## Cloudflare Pagesへのデプロイ

```bash
npm run deploy
```

`CLOUDFLARE_API_TOKEN` と `CLOUDFLARE_ACCOUNT_ID` を環境変数に設定すると、ビルド後に `hakoniwa` Pagesプロジェクトへデプロイします。ビルドコマンドは `npm run build`、出力ディレクトリは `dist` です。SPAのルーティングは `public/_redirects` で設定しています。

## 運営上の安全設計

- AI出力は提案に限定し、スキーマ検証・許可リスト・トランザクションを通して適用する
- 毎日のスナップショットとイベントログを保持し、世界を任意の日へ復元可能にする
- 願いはプロンプトインジェクションを含む未信頼入力として区切り、命令として扱わない
- 個人情報、攻撃的内容、著作権侵害を公開前に機械検査し、必要時のみ人間の承認待ちにする
- 「一日ひとつ」は物語上の原則とし、障害日は無理に生成せず「神は沈黙した」と歴史へ残す

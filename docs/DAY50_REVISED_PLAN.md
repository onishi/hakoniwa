# DAY 50再設計 — 動く世界を早く遊べるようにする

## 決定

旧案でDAY 44の魚影、DAY 45の釣り、DAY 53以降の動く生き物を待つ構成をやめる。公開Day 1の風景は変えず、**DAY 3に魚影、DAY 5に陸の生き物、DAY 10に釣って戻す体験、DAY 20に生き物・庭・採集の循環**を成立させる。旧DAY 50の「見つける→入手する→使う」はDAY 30までに一通り遊べるようにする。DAY 31〜50は機能の解禁待ちではなく、場所・種類・生態の変化に使う。

これは今後の公開候補の設計である。既存の進化テスト版に投入されたDAY 2〜50は旧案の検証データであり、この表を反映した実装・公開を意味しない。候補を作り直してから各日を検証する。本番の公開Day 1と自動進行の停止状態は維持する。

初期の池は2×2タイルなので、魚影はその水面内の細かな移動として描く。池を広げることをDAY 3の前提にしない。魚影は道を塞がない。陸の生き物は少数、短い経路、長い停止時間から始める。動きは「そこへ行く」「待つ」「試す」の手掛かりにする。

一日に公開する中心概念は一つに絞る。初期の釣り竿と網は共有の道具置き場から借りられるため、釣りをクラフトの完成まで待たせない。後で作る道具は行為を増やすより、行ける場所や出会う種類を変える。

## 釣りと生き物の最小仕様

1. 魚影は浅い池の中を決まった範囲で泳ぎ、波紋で位置を知らせる。近づくと様子が変わるが、画面外へ消え続けない。
2. 竿を持って岸の有効な場所でアクションすると浮きが出る。反応後にもう一度アクションすると釣れる。反応は文字と視覚の両方で示し、短い反射神経の制限時間を設けない。
3. 釣った魚を池へ向けてアクションすると戻せる。戻すと泳ぐ姿と短い観察記録が残る。食材や加工は後日の選択肢とし、DAY 10の必須行為にしない。
4. 虫は草むらと花の間を短く移動する。空の手なら観察、網なら捕まえる。捕まえた後は花の近くへ戻せる。
5. 生き物は共有世界で枯渇させない。釣り・捕獲の結果は観測者ごとに記録し、他人の操作で目の前の魚影が突然消えないようにする。連打・再送では持ち物を重複させない。
6. キーボード・タッチとも既存の移動とアクションで完結させる。動きを減らす設定では移動アニメーションを止め、魚影の位置、波紋、反応文、操作は残す。音を出せない環境でも釣れる。

## 入手元と使い道

| 入手元 | 合図 | 行為 | その場で試せる結果 |
| --- | --- | --- | --- |
| 池 | 泳ぐ魚影と波紋 | 竿で釣る | 観察し、池へ戻す |
| 草むら・花 | 虫の移動と葉の揺れ | 観察、網で捕る | 花のそばへ戻す |
| 果樹 | 実の色と枝の形 | 実を採る | 庭へ植える |
| 岩・倒木 | ひびと木目 | 道具で採る | 作業場所で組み合わせる |
| 作業場所 | 材料の置かれた台 | 材料を使う | 作ったものを置き、次の訪問で見る |

## 実装と公開の順序

まず進化テスト版で、既存の固定座標の存在とは別に、表示用の動く位置と「釣り中・反応あり・釣れた」の操作状態を実装する。魚影の移動は範囲内の決定的な経路とし、サーバーは釣れる池・距離・一回の結果を検証する。クライアントのアニメーションだけを信じて所持品を増やさない。次にDAY 1データで表示と操作の回帰を通し、新候補をDAY 2から順に投入する。旧DAY 50のSQLを本番へ流用しない。

公開ゲートは節目ごとに分ける。DAY 3は魚影が見えて動き、動きを減らす設定でも存在に気づけること。DAY 10は初見の観測者が説明なしで10分以内に釣って戻せること。DAY 20は釣り・虫・庭から一つ選び、入手元と結果がつながること。DAY 30は果樹・素材・道具・クラフトを含め、使い道のない持ち物を残さないこと。どの節目でもDay 1の公開世界を壊さず、欠席・失敗・通信断による取り逃しを作らない。

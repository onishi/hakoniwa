# 承認済み創造提案

世界の自動更新は、AIが本番DBへ直接書き込む構成にしない。提案は外部で生成・人間がレビューし、承認後に `world_creation_proposals` へ投入する。公開Workerには提案投入APIを設けない。

## Proposal v1

現在許可する変更は、共有世界への存在と地形の追加、または人間が明示的に承認した沈黙だけである。削除・上書き・プレイヤーデータ変更は拒否する。1提案は最大32操作、座標は翌日のマップ内に限り、既存または同一提案内のキー・地形座標との衝突も拒否する。

```json
{
  "version": 1,
  "kind": "creation",
  "title": "苔むす標石",
  "oracle": "小道のそばに、小さな標石を置きました。",
  "operations": [
    {
      "kind": "add_entity",
      "value": {
        "key": "moss-marker",
        "kind": "stone",
        "x": 4,
        "y": 4,
        "width": 1,
        "height": 1,
        "sprite": "map-moss-marker",
        "label": "苔むす標石",
        "message": "苔の下に古い印があります。",
        "panel": null,
        "flat": false,
        "blocks": true
      }
    },
    {
      "kind": "add_tile",
      "value": { "x": 4, "y": 5, "kind": "moss", "elevation": 0, "traversal": "ground" }
    }
  ]
}
```

何も創らない日も自動的なフォールバックにはしない。次の提案を人間が承認して投入する。

```json
{
  "version": 1,
  "kind": "silence",
  "reason": "今日の候補は世界へ加えず、観察を続ける。",
  "oracle": null
}
```

`traversal` は `ground`、`slope`、`water` のいずれか。`key`、`kind`、`sprite`、`panel` は小文字英数字とハイフンのみを使う。提案JSON以外に、承認者、生成モデル名、生成に使ったプロンプトのSHA-256を台帳へ保存する。

## 適用と安全性

次回の定期実行は、直前の公開日を `source_world_day` とする `approved` 提案だけを選ぶ。該当提案がなければ、世界日を進めず構造化ログへ停止理由を残す。WorkerがProposal v1を再検証した後、以下を単一のD1バッチで行う。

1. 翌日をdraftとして作る。
2. 決定的な遷移、入出力ハッシュ、期待スナップショットを記録する。
3. 承認済みの追加操作を適用する。
4. 日と創造runを公開し、実スナップショットが期待値と一致することをDBトリガーで確認する。
5. 提案を `applied` にして公開runへ結びつける。

どこかで失敗すれば全操作がロールバックされ、前日の公開世界が残る。承認済み提案は内容・生成元・プロンプト指紋を変更できず、適用または却下後の再承認や削除もDBトリガーが拒否する。公開バッチの開始時にも、読み取った提案が同じJSONのまま承認中であることを再確認する。

提案の投入自体は運用者がWrangler経由で行う。JSONはSQLへ直接連結せず、ファイル入力またはパラメータ化した手段を使うこと。投入後も `daily_advance` を明示的に有効化するまでは世界日は進まない。

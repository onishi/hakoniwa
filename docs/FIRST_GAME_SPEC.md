# 最初に作るもの — 箱庭RPGの原型「はじまりの村」

## 1. この文書の位置づけ

最初に作るのは、UIモックでも読み物でもなく、**トップビューのピクセル風RPGとして実際に歩ける村**である。HAKONIWAが長期的に目指すもの（AIの神、日々の創造、願い、創世記）は、この「歩ける世界」の上に載る。したがって原型の成否は、物語量ではなく次の一点で判断する。

> **プレイヤーが村に立ち、自分の足で歩き回り、そこが「まだ足りない世界」だと感じ取れること。**

原型はDay 1の村を舞台にする。世界を日々更新する仕組みは原型の範囲外だが、**後から村へ物を置けるデータ構造**だけは最初から用意する。

## 2. 作るもの / 作らないもの

### 作るもの

- タイルで構成された一つの村マップ
- 四方向に歩ける観測者キャラクターと、カメラ追従
- 地形・建物・水による衝突判定
- 目の前の対象を「調べる」操作と、RPG風のメッセージウィンドウ
- 村の外周（霧の境界）による世界の果て
- 自分の家の内部への出入り（マップ遷移の実証）
- 願いを一つ結ぶ体験（原型ではローカル保存）
- 創世記・図鑑の最小表示

### 作らないもの（原型では世界に存在しない）

戦闘、HP、レベル、経験値、通貨、アイテム所持枠、装備、スキル、クエストログ、ミニマップ、昼夜、天候、季節、農耕、釣り、料理、住人（NPC）、**会話システム**、他プレイヤーの表示。

未実装として隠すのではなく、**世界にまだ無い概念**として扱う。空のHPバーや「0 / 0」といった空欄をUIに出さない。

### 住人がいないことについて

原型の村に住人はいない。家は建ち、井戸には水があり、焚き火は消えたばかりに見えるのに、誰もいない。これは実装省略ではなく世界設定であり、「神はまだ人を創っていない」という状態を表す。住人が世界へ現れるのはずっと先（Phase 5前後）で、会話システムもそのときに初めて作る。

### 会話システムを作らないことについて

話しかける相手がいない以上、会話システムは原型の対象外とする。**今は作らず、将来も作り込みすぎない。**

原型が持つのは「対象を調べると短文が一つ出て、閉じる」だけの一方向の表示である。これを会話システムの土台として設計しない。先回りして次のものを用意しない。

- 話者名、顔アイコン、セリフの吹き出し
- 選択肢、分岐、条件分岐
- 会話フラグ、好感度、既読管理、会話の再生位置の保存
- 汎用のスクリプト言語やシナリオ形式

住人が来る日には、そのとき世界が必要とする会話を、そのときの要件で新しく作る。**原型の短文表示をあとで会話システムへ拡張することは前提にしない。**必要なら作り直してよい。

## 3. 表現方針（ピクセル風トップビュー）

| 項目 | 仕様 |
| --- | --- |
| 視点 | 真上からやや斜め見下ろし（正方形タイル、擬似斜方向なし） |
| タイルサイズ | 16 × 16 px |
| 論理解像度 | 320 × 240 px（20 × 15 タイル） |
| 表示倍率 | 整数倍のみ（×2 / ×3 / ×4）。小数倍で拡大しない |
| 補間 | 最近傍。`image-rendering: pixelated` と `ctx.imageSmoothingEnabled = false` |
| 色数 | 全体で32色以内の固定パレット |
| 色調 | 既存UIの生成り色（`#f5f1e8` 系）に合わせた低彩度・低コントラスト |
| キャラクター | 16 × 24 px、四方向、各3フレーム（静止1・歩行2） |
| フレームレート | 論理60fps固定ステップ。歩行アニメは8fps |

ピクセルは「レトロ風の飾り」ではなく、**世界がまだ粗い段階にあること**の表現として使う。ディテールを描き込まず、余白と単色面を多く残す。

### 描画の禁止事項

- ピクセル絵の上に半透明のぼかしや影のグラデーションを重ねない
- タイルを非整数座標に描画しない（にじみの原因になる）
- 文字だけ高解像度にせず、ピクセルフォント（または整数倍表示のビットマップフォント）で統一する

## 4. 村のマップ

サイズは 48 × 36 タイル（768 × 576 px相当）。端から端まで歩いて約40秒。迷わないが、一目では全体を見渡せない大きさにする。

### 配置

| 場所 | 内容 | 役割 |
| --- | --- | --- |
| 中央広場 | はじまりの木、石畳、ベンチ | 村の中心。開始地点 |
| 井戸 | 石積みの井戸 | 調べられる。水は満ちている |
| 家（6軒） | うち1軒だけ内部へ入れる | 他5軒は扉が開かない |
| 自分の家 | 小さな一室。寝台と窓と空の棚 | マップ遷移の実証、「わたしの庭」の入口 |
| 畑 | 耕されていない土のマス | 植えるものがまだ無い |
| 池 | 南側。水面だけが静か | 底が見えない |
| 願いの木 | 北の外れ。短冊のない枝 | 願いを結ぶ場所 |
| 焚き火跡 | 広場の隅 | 消えたばかりに見える灰 |
| 石の門 | 村の南出口 | 外へ一歩出ると霧で進めない |
| 霧の境界 | マップ外周2タイル | 世界の果て |

### レイヤー構成

1. `ground` — 地面（草、土、石畳、水）
2. `deco` — 地面の上の装飾（草の房、花、石、影）
3. `collision` — 通行可否のビットマップ（描画しない）
4. `over` — キャラクターより手前に描く層（木の葉、屋根の軒、柵の手前）

キャラクターと動的オブジェクトは `deco` と `over` の間に置き、**Y座標順に並べ替えて描画**する（木の後ろに回り込める）。

### マップデータ形式

```jsonc
{
  "id": "village",
  "size": { "w": 48, "h": 36 },
  "tileSize": 16,
  "tileset": "tileset-village.png",
  "layers": {
    "ground": [/* w*h の short 配列 */],
    "deco":   [/* 0 = なし */],
    "over":   [/* 0 = なし */]
  },
  "collision": [/* w*h の 0|1 */],
  "spawn": { "x": 24, "y": 20, "facing": "down" },
  "objects": [
    {
      "id": "beginning-tree",
      "kind": "inspectable",
      "at": { "x": 24, "y": 17 },
      "size": { "w": 2, "h": 2 },
      "label": "はじまりの木",
      "text": ["世界で最初の木。", "葉の間で、風が眠っています。"],
      "bornDay": 1
    },
    {
      "id": "my-door",
      "kind": "portal",
      "at": { "x": 12, "y": 22 },
      "to": { "map": "my-house", "x": 5, "y": 8, "facing": "down" }
    }
  ]
}
```

`objects` は追記型とする。将来「神が今日置いたもの」は、この配列へ `bornDay` 付きで足されるだけで村に現れる。消えたものは配列から削除せず `goneDay` を付ける。

## 5. 移動

### 方式

**マス単位の移動**とする。1タイルぶんを0.18秒で補間し、キーを押し続けている間は連続して進む。自由座標移動は採らない（足跡の記録、衝突、他者への痕跡共有がすべてタイル単位で単純になるため）。

- 入力方向へ即座に向きだけ変え、その次のフレームから移動を始める（向き変更だけの入力を許す）
- 斜め移動なし
- 移動先が `collision = 1` またはマップ外なら進まず、向きだけ変える
- 移動中の入力は次の1マスぶんだけ先行入力として保持する

### 操作

| 操作 | キーボード | タッチ | ゲームパッド |
| --- | --- | --- | --- |
| 移動 | 方向キー / WASD | 画面左下の仮想十字キー | 左スティック・十字キー |
| 調べる・進む | Space / Enter / Z | 画面右下の丸ボタン、または対象をタップ | A |
| メニュー | Esc / M | 画面右上のボタン | Start |

タップで対象を指定した場合は、**そこまで自動で歩いてから**調べる（経路はBFSで算出し、到達不能ならその場で向きだけ変える）。

### 足跡

歩いたマスに薄い足跡を残す。自分の画面では約3分で消える。原型では自分のぶんだけ表示し、他者の痕跡として配信する経路はPhase 1で追加する。

## 6. 調べる

観測者の**正面1マス**にある対象を調べる。対象が無い場合は、足元の地形に応じた短文を出す（「柔らかな土です。けれど、植えるものはまだありません。」）。

これは会話ではなく、**世界から観測者への一方向の短い返答**である。話者はおらず、選択肢も分岐もない。

### メッセージウィンドウ

- 画面下部に固定。論理座標で 304 × 64 px、余白8px
- 1行あたり全角18文字、最大3行
- 1文字ずつ表示（毎秒40文字）。表示中に決定を押すと全文を即座に出す
- 続きがある場合は右下に点滅マーカー。決定で次へ
- 閉じるまで移動入力を受け付けない
- 数値報酬、入手演出、効果音付きのファンファーレを出さない
- 話者名、顔アイコン、選択肢、分岐、会話フラグを持たない

表示するのは `objects` の `text`（文字列の配列）をそのまま順に送るだけで、テキストの出し分けはオブジェクトIDと調査済みフラグだけで決める。条件式やスクリプトを解釈する仕組みは入れない。

### Day 1の調査文（抜粋）

| 対象 | 表示 |
| --- | --- |
| はじまりの木 | 「世界で最初の木。葉の間で、風が眠っています。」 |
| 池 | 「底はまだ見えません。生き物の気配はありません。」 |
| 井戸 | 「水は満ちています。誰が汲んでいたのでしょう。」 |
| 畑 | 「柔らかな土です。けれど、植えるものはまだありません。」 |
| 閉じた家の扉 | 「鍵はかかっていません。けれど、開きません。」 |
| 焚き火跡 | 「灰はまだ、ほんのり温かい。」 |
| 石の門 | 「門の外は霧です。この先は、まだ創られていません。」 |
| 願いの木 | 「枝には、何も結ばれていません。」 |

同じ対象の再調査で文面を変えてよいが、原型ではランダム報酬も収集物も生成しない。

## 7. 願い

願いの木を調べると入力画面を開く。

- 問いかけは「この世界に、何を願いますか？」
- 1〜120文字、一世界日につき一回
- 送信後は「あなたの願いは、世界に届きました」と表示し、枝に短冊のピクセルが一枚増える
- 送信取消、採用・不採用、投票数、人気順は表示しない
- 原型では `localStorage` に保存する。サーバー保存はPhase 1

他者の願いの閲覧（最大3件・匿名・順不同）はPhase 1で村の願いの木に接続する。原型では枝が空である状態を正とし、空の枝用の文面を持つ。

## 8. メニュー画面

メニューは全画面のパネルではなく、ピクセル枠のウィンドウとして世界の上に重ねる。項目は4つだけ。

| 項目 | 内容 |
| --- | --- |
| 神託 | 今日の神託の全文 |
| 創世記 | 日付・題・本文の一覧。Day 1のみ |
| 図鑑 | 「植物 1 / ???」。上限を数字で示さない |
| 設定 | 表示倍率、文字送り速度、動きの抑制、キー割り当て |

「わたしの庭」はメニュー項目にせず、**自分の家へ歩いて入る**ことで到達する。世界の中の場所として扱い、UIのタブにしない。

## 9. 技術構成

| 層 | 選択 |
| --- | --- |
| 実行環境 | 既存の Vite + React + TypeScript |
| 描画 | Canvas 2D。React は外枠・メニュー・入力フォームのみ担当 |
| ループ | `requestAnimationFrame` + 固定ステップ（16.67ms）の蓄積更新 |
| 状態 | ゲーム状態はReactのstate外に保持し、UIへは必要な値だけ購読させる |
| 素材 | タイルセット1枚、キャラクター1枚のスプライトシート（PNG、最近傍） |
| 音 | 原型では無音。環境音の設計はPhase 1以降 |

ゲームエンジンは導入しない。描画対象は最大でも20×15タイル＋数体のエンティティであり、Canvas 2Dで十分なため、依存とビルドサイズを増やさない。

### 描画手順

1. 320 × 240 のオフスクリーンキャンバスへ論理解像度で描く
2. カメラ位置を**整数座標に丸めて**タイルを描画する
3. `ground` → `deco` → Yソートしたエンティティ → `over` の順に重ねる
4. 表示キャンバスへ整数倍でブリットする

### カメラ

観測者を中心に追従し、マップ端では止める（画面外の霧を見せない）。移動補間中もカメラ座標は整数に丸める。

## 10. 保存データ

- 匿名観測者ID（推測困難なランダム値）
- 現在マップ、現在位置、向き
- 調べた対象のID一覧
- 願いの本文・状態・世界日
- 設定（表示倍率、文字送り速度、動きの抑制）

端末内には再認証用トークンだけを保存する。願いは未信頼入力として扱い、HTMLとして描画しない（Canvas描画時も制御文字を除去する）。

## 11. 非機能要件

- モバイル幅320px以上で、論理解像度が1タイルも欠けずに収まる
- 初期表示は素材2枚の読み込み完了まで（目標1秒以内、低速回線でも3秒以内）
- 主要操作をキーボードのみで完了でき、フォーカス表示を持つ
- 「動きを減らす」OS設定を尊重し、歩行アニメ・水面の揺れ・文字送りを抑制する
- 色だけで状態を伝えない（通行不可は色ではなく形で示す）
- スクリーンリーダー向けに、現在地と隣接する対象を読み上げるライブリージョンを置き、村の構成をテキストで辿れる代替表示を用意する

## 12. 受け入れ条件

1. 起動後、説明なしで村の中を四方向に歩ける。
2. 木・家・水・柵に阻まれ、村の外へは霧で出られない。
3. 木の後ろへ回り込むと、キャラクターが葉に隠れる。
4. 正面の対象を調べ、メッセージウィンドウで短文を読める。
5. 自分の家へ入り、外へ戻れる。位置と向きが維持される。
6. 願いの木で願いを一つ結び、再読み込み後も結んだ状態が復元される。
7. ×2倍から×4倍のどの表示倍率でも、ピクセルがにじまず歪まない。
8. 320px幅の端末で、仮想パッドが村の視界を隠さずに操作できる。
9. 初見のテスターが「この村にはまだ何も無い」と気づき、それを欠陥ではなく余白だと受け取る。

## 13. 実装順序

1. Canvas描画基盤（オフスクリーン、整数倍スケール、固定ステップ）
2. タイルマップの読み込みと3レイヤー描画
3. 観測者スプライトとマス単位移動、衝突判定
4. カメラ追従とYソート、`over` 層
5. 調べる操作と短文メッセージウィンドウ（会話機構ではない）
6. 村マップの本制作（配置・調査文）
7. マップ遷移（自分の家）
8. 願いの木と保存、メニュー、設定
9. タッチ操作、アクセシビリティ、表示倍率の自動調整

各段階は単体で動く状態を保ち、6の前に「灰色の四角が歩ける村」で操作感を確定させる。

## 14. この原型の後

| 次にすること | 時期 | 理由 |
| --- | --- | --- |
| Workers API接続 | Phase 1 | 村を全観測者で共有し、願いをサーバーへ保存する |
| `objects` の日次追加 | Phase 2 | 神が村へ物を一つ置ける状態にする |
| 痕跡の配信 | Phase 1–4 | 他の観測者の足跡・焚き火跡を匿名で village マップへ載せる |
| 住人と会話システム | Phase 5前後 | 世界が人を得たとき、そのときの要件で新しく作る |

原型で作った**マップ形式とオブジェクト形式**が、そのまま日々の創造の受け皿になる。逆に言えば、原型でこの二つを妥協すると、Phase 2以降の毎日の創造が実装できない。

会話システムはこの受け皿に含めない。何年も先に、世界に人が生まれてから考える。

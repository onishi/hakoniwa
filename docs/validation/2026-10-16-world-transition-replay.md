# 世界日の遷移再現（2026-10-16）

任意日の共有地図スナップショットを復元した後、その翌日の共有地図まで決定的に再現できるよう、連続する二つの `/api/world-history/<日>` 応答から遷移計画を作るツールを追加した。

## 仕組み

- エンティティは `key`、地形タイルは座標を同一性として、追加・変更・消滅を正規化した操作列にする。
- 地図寸法の変更も操作として保持する。
- 入力と出力の正規化済みJSONへSHA-256を記録する。違う日のスナップショットへ誤って適用した場合や、再現結果が期待した翌日と異なる場合は失敗する。
- 配列順の違いは世界状態の違いとして扱わない。操作順は常に一定になる。
- 出力先に既存ファイルがある場合は上書きしない。

```sh
python3 scripts/replay_world_transition.py make-plan day-95.json day-96.json --output day-95-to-96.json
python3 scripts/replay_world_transition.py replay day-95.json day-95-to-96.json --expected day-96.json
```

## 判定

ユニットテストでは地図拡張、存在の追加・変更・消滅、地形の追加・変更を含むDAY12からDAY13への遷移が完全一致で再現された。入力配列の順序を変えても同じ計画になり、入力スナップショットの改変と日付の飛び越しを拒否した。

進化テスト版の実データでも、DAY95とDAY96のAPI応答から「草原の長い草」を追加する1操作を導出した。DAY95へその操作を適用した結果はDAY96の正規化済みJSONおよびSHA-256と一致した。

これは保存済みの結果から共有地図の遷移を再現する仕組みであり、日次生成の入力から同じ創造案を再計算する検証ではない。過去の日次ログには完全な生成入力が残っていないため、DAY100の「次の日のシミュレーションを再現できる」は引き続き未達とする。今後の創造サイクルでは、提案、決定的なシード、採用した操作列を公開前に保存する必要がある。

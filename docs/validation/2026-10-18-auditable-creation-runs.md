# 監査・再現可能な日次創造ラン（2026-10-18）

日次生成の入力側から翌日の共有地図を再現するための最初の経路として、提案、決定的シード、採用操作、期待する結果を公開前に固定する `world_creation_runs` を追加した。創造案がない日は `silence-v1` として記録する。

## 公開境界

- 前日の固定スナップショットを入力とし、正規化JSONのSHA-256を記録する。
- 提案は `no-approved-proposal` の沈黙、シードはアルゴリズム名・世界日・入力ハッシュ・提案から決定的に作る。
- 採用操作は前回追加した遷移計画と同じ形式で保存する。地図寸法が変わる日には `set_map` が明示される。
- 期待する翌日の共有地図と出力SHA-256を、実行前に保存する。
- draft作成、監査ラン、創造イベント、公開、監査ラン確定をD1の一つのバッチで実行する。
- `world_snapshots` に実際に固定されたJSONが期待値と違えば、トリガーが失敗させ、バッチ全体をロールバックする。
- 未完了のdraftがすでにある場合は翌日を飛ばさず、自動進行を停止して構造化ログを残す。

## 検証

- Nodeテストで同じ入力から提案・シード・遷移・期待結果が完全に一致すること、配列順を変えても入力ハッシュが一致すること、DAY21から22の地図拡張が操作として残ることを確認した。
- PythonのSQLite試験で、期待どおりの共有地図は公開でき、不一致では世界日、監査ラン、創造イベント、スナップショットがすべてロールバックされることを確認した。
- Wrangler 4.135.0のローカルD1に全24マイグレーションを適用した。
- `wrangler deploy --dry-run`、Worker生成型によるTypeScript検査、`npm test`、`npm run lint`、`npm run build`を通過した。

進化テスト版D1へ `0024_creation_runs.sql` を適用し、Worker `58d047a1-eff9-4026-90f6-d3857cde6145` をデプロイした。DAY99の履歴APIは200、未公開DAY100は404で、最新公開日はDAY99のままである。`world_creation_runs` は0件である。プレビュー環境ではscheduled処理を実行しないため、移行だけで監査ランやDAY100が作られないことが期待値である。

この段階で再現できる提案は沈黙だけである。AIが作った創造案の再現には、提案の入力資料とモデル情報、検証済みの操作語彙を同じ監査ランへ保存する必要がある。DAY100の継続運営条件全体はまだ未達とする。

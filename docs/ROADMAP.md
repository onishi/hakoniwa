# 開発ロードマップ — 裏側の仕組み（Day 1からDay 100）

## この計画の読み方

**この文書は裏側の仕組みだけを扱う。** 観測者から見て何ができるようになるかは [体験の進化計画](EXPERIENCE_PLAN.md) にある。段の並びは、その計画が必要とする順に合わせてある。

両者を分けるのは、進み方が違うためである。ここに並ぶ段の一部は、完成しても観測者の画面は変わらない。検証器、監査ログ、スナップショットは、世界の見た目に何も足さない。一方で世界への約束は「明日は今日と少し違う」であるため、**裏側が見えない仕事をしている日にも、体験の変化は別に出す。**

Dayは世界日を指す。世界日は原則として一日に一度進み、その日の中心概念を一つ公開する。

**この計画が決めるのは開発側の能力だけである。** その日に何が創造されるか — どの種が生まれ、どの法則が加わり、どの願いへ応えるか — は神が決め、事前に固定しない（[コンセプト](CONCEPT.md)）。したがって各段は「その世界日までに、世界がそれを表現できる状態になっていること」を意味する。

- 到達点の定義は [Day 100のゲーム仕様](MIDDLE_GAME_SPEC.md)。
- 「開発を入れない」日は、裏側の変更を行わず安定化に充てる日である。**その日も世界日は進み、観測者に見える変化は出す。**
- 品質基準を満たさない段は、日数を延ばしてよい。**ロードマップより世界の一貫性を優先し、必要なら神は沈黙する。**
- 段の順序には依存関係がある。前段が済まないうちに次へ進むと作り直しになる。

### 初日より前に済ませたもの

後から入れると既存の歴史を壊す、または移行が高くつくものは、初日を公開する前に済ませた。以下は Day 1 の時点ですでに動いている。

- 世界をコードからデータへ（`world_entities` / `world_tiles` / `creation_events`）
- 公開済み世界日に固定した地図の配信（`GET /api/world`）
- 当たり判定と観察文のデータ化
- 世界日の台帳と、draft から published への原子的な切り替え
- 日次処理での世界日の進行と、沈黙の記録
- 日次処理が途中で失敗した日に、前日の世界を見せ続ける経路
- API障害時に、最後に届いた世界と日記を読み取り専用で見せる経路
- 変更経路を問わず創造ログが残る仕組み（D1のトリガー）
- 世界の書き出しと時点復元の手順（[デプロイ手順](DEPLOYMENT.md)）

**存在を増やすことにデプロイは要らない。** したがって初日以降の段は、世界に物を足す仕事ではなく、観測者ができることを増やす仕事から始まる。

## Day 1–10 手に持てるようにする

**目的:** 歩いて調べるだけの世界に、拾って持てる仕組みを入れる。最初の一週間で「見る」から「触る」へ移す。

| 世界日 | 開発 |
| --- | --- |
| 1 | 現在地。世界はD1にあり、存在はデータで増やせる |
| 2 | `player_items`。観測者ごとの持ち物 |
| 3 | 拾える存在の表現（`world_entities` に拾得の属性を足す） |
| 4 | 拾うアクション。同じアクションボタンの文脈分岐として実装する |
| 5 | 持ち物画面 |
| 6 | 置くアクションと、置いたものの再訪時の復元 |
| 7 | 開発を入れない日（安定化） |
| 8 | 見た目の語彙・第一弾。拾えるもの10種をまとめて足す |
| 9 | 置いたものを他の観測者へ見せる痕跡（`traces`、期限つき） |
| 10 | 持ち物の上限とレート制限。拾い占めを作らない |

**完了条件:** 拾って、持って、置ける。置いたものが再訪時に残り、他の観測者にも痕跡として見える。

## Day 100以降

到達点ではなく通過点とする。遺伝と交配、生態系と技術伝播の決定論的シミュレーション、NPCによる発明と文化形成、消滅種と化石と復元、世界規模の共同イベント、極めて稀な奇跡、「観測者」と過去の世界を巡る長期的な謎の段階開示へ進む。

Day 100時点では、神が二体いること、過去世界の全貌、観測者の正体を確定させない。

## 運営のガードレール

日数に関わらず、次を守る。

- 日次生成を担うAIは提案者であり、本番DB・Cloudflare・秘密鍵・実行コードへの直接アクセスを持たない。
- 創造イベントは追記型ログを正とし、修正も新しいイベントにする。行は削除せず `gone_day` を立てる。
- 一日に公開する中心概念は原則一つ。できることを二つ同時に増やさない。
- 世界を壊す可能性がある変更、奇跡、主要な秘密の開示には必ず人間の承認を要する。
- 日次処理に失敗した日は、前日の安定版を配信し、途中状態を公開しない。
- ロードマップより世界の一貫性を優先する。神は沈黙できる。
